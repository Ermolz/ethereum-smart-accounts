# Нотатки для себе: EIP-7702 без зубріння

Це коротка опора для повторення поруч зі [слайдами](index.html). Повний усний текст — у [виступі](03-speech.md), пояснення з нуля — у [посібнику](02-learning-guide.md).

## Головна модель

**Мій акаунт зберігає адресу, але може працювати за програмою, яку я обрав.**

Назви адресу акаунта **A**, а адресу програми — **D**. Ethereum записує в A покажчик на D. Коли викликають A, код береться з D, але працює з адресою й даними A. Саме призначення коду не переносить токени на D.

Запам’ятай два запитання: **«Яку програму дозволено використовувати?»** і **«Яку дію дозволено виконати?»** На перше відповідає авторизація делегування. Друге має перевірити сама програма. Вибір поганої програми небезпечний: протокол не додасть їй відсутніх перевірок.

## Як пояснити кожен слайд

| Слайд | Що сказати своїми словами | На що показати |
|---|---|---|
| 1. «Третій тип» акаунта? | «Це звичайний EOA з новими можливостями. Адреса залишилася, додався покажчик на код». | Адреса в картці → рядок `code` → стрілка до реалізації |
| 2. Ключ, код і право керування | «EOA керує ключ. Контрактом керують правила коду. Делегований EOA має код, але ключ теж зберігає контроль». | Три рядки таблиці; особливо остання клітинка праворуч |
| 3. Делегування коду | «Спочатку перевіряють підпис, потім записують покажчик, потім запускають програму. Право на конкретну дію вона перевіряє окремо». | Три блоки зліва направо, потім смужка «Адреса / Баланс / Сховище» |
| 4. Approve + swap | «Дозвіл витратити токени й обмін можна зібрати в одну транзакцію. Інша сторона може оплатити газ». | Два прямокутники зверху → один пакет унизу → блок спонсора |
| 5. Що переживає revert | «Обмін може не відбутися, а призначена програма залишитися. Це дві різні частини обробки». | «Зберігається» ліворуч і «Зміни виконання відкочуються» праворуч |
| 6. Програмованість і відповідальність коду | «7702 призначає код, 4337 організовує обробку операцій. Безпеку конкретних дій забезпечує програма». | Порівняння ліворуч, список перевірок праворуч, нагадування про ключ |
| 7. Та сама адреса. Програмована поведінка. | «Зручність зростає, але треба знати обраний код, дозволи й наслідки помилки». | Головна фраза, потім дати Pectra та Uniswap |

Не читай схеми слово в слово. На кожному слайді достатньо однієї головної думки, а стрілки й таблиці допомагають її показати.

## Словник без складних формул

| Термін | Що він означає тут |
|---|---|
| EOA | Акаунт, яким керує приватний ключ |
| Смарт-акаунт | Акаунт із програмованою поведінкою; це не обов’язково лише EIP-7702 |
| Authority / A | Акаунт, для якого підписали делегування |
| Delegate / D | Адреса, звідки береться код програми |
| Sender | Відправник зовнішньої транзакції; ним може бути спонсор |
| Authorization | Підписаний дозвіл призначити код; не готовий дозвіл на довільні платежі |
| `chain_id` | Ідентифікатор мережі; `0` допускає різні мережі за решти виконаних умов |
| `nonce` | Лічильник для перевірки актуальності дозволу; у програми можуть бути власні лічильники дій |
| `0x04` | Номер типу транзакції EIP-7702 |
| `0xef0100 \|\| D` | 23-байтовий покажчик: три байти префікса плюс адреса D; не повна програма |
| EVM | Середовище Ethereum, яке виконує код |
| `storage` | Постійні дані акаунта, наприклад записаний ліміт |
| `msg.sender` / `tx.origin` | Викликач поточного кроку / початковий відправник транзакції |
| Approve / allowance | Надати дозвіл витрачати токени / величина такого дозволу |
| Swap / Router | Обмін / контракт, через який організовують обмін |
| Batch / атомарність | Кілька викликів у пакеті / усі потрібні дії успішні або їхні зміни відкочуються |
| Revert | Відкат змін невдалого виконання |
| Газ / спонсор | Вимір роботи мережі / сторона, яка може оплатити її в ETH |
| UserOperation / bundler / EntryPoint | Запит користувача / його збирач і відправник / контракт обробки в ERC-4337 |
| Paymaster | Компонент ERC-4337, який може брати участь в оплаті операції |

## Три прості приклади

**1. Токени залишаються на місці.** На A є 100 токенів. Власник призначає код D. Саме делегування не переказує ці 100 токенів до D. Програма отримує можливість працювати від імені A, тому її перевіркам треба довіряти.

**2. Дозвіл і обмін одним пакетом.** Дозволу для Router немає. Програма робить `approve(Router, 100)`, потім обмін. Якщо обмін падає й помилка скасовує весь пакет, новий дозвіл повертається до нуля. Якщо код дозволяє частковий успіх, результат може відрізнятися.

**3. Невдалий обмін і програма, що залишилась.** Делегування прийняли, але виконання відкотилося. Обміну немає, покажчик на код є; витрачений газ оплачується. Подальша авторизація з нульовою адресою прибере покажчик, але старі дані акаунта та раніше видані дозволи токенів сама не очистить.

Числа умовні. Це приклади для розуміння, а не інструкції для відправлення транзакцій.

## Повторення за 15–20 хвилин

1. **0–3 хв:** прочитай головну модель та два запитання про дозволи.
2. **3–6 хв:** переглянь сім слайдів із таблицею підказок. Назви головну думку кожного.
3. **6–9 хв:** поясни три приклади без підглядання; перевір незнайомі слова.
4. **9–14 хв:** прочитай [виступ](03-speech.md) вголос, перемикаючи слайди та вимірюючи час.
5. **14–17 хв:** повтори застереження нижче й питання 5, 7, 10, 12 у [підготовці до захисту](04-defense-preparation.md).
6. **17–20 хв, якщо є час:** ще раз поясни слайди 3 і 5. Саме тут найпростіше переплутати дозволи та відкат.

## Якщо загубився під час виступу

Зроби паузу й подивися на заголовок. Скористайся однією опорною фразою:

**1:** «Адреса та сама». **2:** «Ключ і код мають різні ролі». **3:** «Обрати програму й дозволити дію — різне». **4:** «Два виклики в одній транзакції». **5:** «Обмін скасовано, делегування залишилося». **6:** «Перевірки залежать від коду». **7:** «Та сама адреса, нові можливості».

Покажи відповідний елемент схеми й продовжуй. Якщо забув число або формулу, не вгадуй: поясни їхню роль. Точний запис уже є на слайді.

## Застереження, які не можна загубити

- «Третій тип» — неформальна назва; точно — EOA з делегованим кодом.
- Авторизація призначає код. Право на конкретну дію перевіряє реалізація.
- Делегування тривале; помилка виконання не скасовує вже прийняте делегування.
- Очищення покажчика не очищує `storage` і дозволи ERC-20.
- Пакет атомарний лише за відповідної обробки помилок.
- Спонсор платить ETH; спонсорування не усуває комісію.
- Основний ключ зберігає контроль і може змінити код. Додаткові правила не прибирають цей ризик.
- ERC-4337 доповнює EIP-7702; ліміти й відновлення не виникають автоматично.
- Pectra: **7 травня 2025 року**. Анонс підтримки Uniswap: **2 липня 2025 року**.
